# IFRI MentorLink

## Organisation de l’Équipe

**Version :** 2.0

**Date de création :** 03 Juin 2026

**Statut :** Document de gouvernance officiel

# 1\. Objectif

Ce document définit l’organisation interne de l’équipe IFRI MentorLink.

Il a pour objectifs de :

- définir les responsabilités de chaque membre ;
- uniformiser la méthode de travail ;
- faciliter la collaboration ;
- assurer le suivi du projet ;
- maintenir une progression constante malgré les contraintes de temps.

Ce document fait référence pendant toute la durée du projet.

# 2\. Philosophie de travail

L’équipe adopte les principes suivants :

## Compréhension avant production

Aucun membre ne doit intégrer du code ou une solution qu’il ne comprend pas.

L’utilisation d’outils d’assistance (documentation, IA, ressources externes) est autorisée, mais chaque membre doit être capable d’expliquer ce qu’il produit.

## Documentation continue

Toute décision importante, architecture, convention ou fonctionnalité doit être documentée.

La documentation est considérée comme une partie intégrante du projet.

## Travail collaboratif

Le projet n’est pas divisé en sous-projets indépendants.

Même lorsqu’un membre est principalement affecté à une partie du système, les autres doivent comprendre son fonctionnement général.

L’objectif est que chaque membre puisse présenter le projet dans son ensemble.

# 4\. Processus de prise de décision

Les décisions sont prises selon le processus suivant :

1.  Présentation du problème.
2.  Tour de parole de chaque membre.
3.  Discussion collective.
4.  Recherche d’un consensus.
5.  En cas d’absence de consensus, le Coordinateur Général prend la décision finale dans l’intérêt du projet.

# 5\. Organisation des réunions

## Réunion quotidienne

- Horaire : 18h30 à 20h30.
- Support : Google Meet.

Objectifs :

- suivi des tâches ;
- résolution des difficultés ;
- planification des actions.

## Réunion présentielle

- Tous les deux jours.
- Le dimanche est exclu.

Objectifs :

- développement collaboratif ;
- revue de code ;
- synchronisation générale.

# 6\. Gestion des tâches

Les tâches sont réparties en fonction :

- des compétences ;
- des disponibilités ;
- de la charge de travail.

Toute tâche importante doit être connue des autres membres.

Les développements ne doivent jamais devenir des “boîtes noires”.

# 7\. Gestion des absences

## Absence prévue

Le membre informe le groupe le plus tôt possible.

## Absence non justifiée

Elle est mentionnée dans le compte-rendu de réunion.

## Deux absences consécutives non justifiées

Les responsabilités du membre peuvent être redistribuées temporairement afin de préserver l’avancement du projet.

Cette mesure est organisationnelle et non disciplinaire.

# 8\. Politique GitHub

- Un dépôt GitHub unique.
- Commits réguliers.
- Messages de commit explicites.
- Aucun développement directement sur la branche principale.
- Les modifications importantes doivent être relues avant intégration.

# 9\. Communication

Les outils officiels de communication sont :

| Outil | Utilisation |
| --- | --- |
| WhatsApp | Communication rapide |
| Google Meet | Réunions quotidiennes |
| GitHub | Gestion du code |
| Documentation du projet | Référence technique |

Les décisions importantes prises oralement doivent être retranscrites dans la documentation.

# 10\. Principes de collaboration

Chaque membre s’engage à :

- participer activement aux réunions ;
- demander de l’aide lorsqu’il rencontre une difficulté ;
- aider les autres lorsque cela est possible ;
- respecter les délais fixés ;
- maintenir une attitude constructive et respectueuse.

# 11\. Évolution du document

Cette organisation pourra être adaptée en fonction :

- de l’arrivée du septième membre ;
- de l’évolution du projet ;
- des besoins identifiés collectivement.

Toute modification devra être validée selon le processus de décision défini dans ce document.
