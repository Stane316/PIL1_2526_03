# IFRI MentorLink

## Répartition officielle des responsabilités de l’équipe

**Version :** 1.0

**Date :** 03 Juin 2026

# Objectif du document

Ce document définit les responsabilités principales de chaque membre du groupe IFRI MentorLink.

Il ne s’agit pas de séparer le projet en plusieurs sous-projets indépendants. Chaque membre doit comprendre le fonctionnement global de l’application.

Les responsabilités définissent simplement :

- le domaine principal de contribution ;
- les livrables attendus ;
- les critères permettant de considérer une tâche comme terminée ;
- les interactions avec le reste de l’équipe.

# Principe général de fonctionnement

Chaque membre doit :

- Participer aux réunions quotidiennes ;
- Lire la documentation commune ;
- Comprendre les choix techniques réalisés ;
- Pouvoir expliquer le fonctionnement général du projet ;
- Effectuer des commits réguliers sur GitHub ;
- Participer aux revues de code.

Aucun membre ne doit travailler de manière totalement isolée.

# 1\. Stan

## Rôle principal

**Chef de projet / Architecte logiciel / Responsable Documentation**

## Mission

Assurer la cohérence globale du projet.

Stan coordonne les travaux de l’équipe, valide les choix techniques, organise les réunions et veille au respect du cahier des charges.

## Responsabilités

### Gouvernance

- Organiser les réunions.
- Préparer les ordres du jour.
- Suivre l’avancement général.
- Identifier les blocages.

### Architecture

- Définir l’architecture logicielle.
- Maintenir la cohérence entre Frontend, Backend et Base de données.
- Valider les évolutions techniques.

### Documentation

- Superviser la rédaction des documents.
- Maintenir la documentation à jour.
- Vérifier que chaque décision importante est documentée.

### GitHub

- Superviser le dépôt GitHub.
- Relire les Pull Requests.
- Valider les fusions importantes.

## Livrables

- Documentation complète.
- Architecture validée.
- Organisation de l’équipe.
- Validation finale des modules.

## Critères de validation

Le rôle est considéré comme correctement rempli lorsque :

- tous les membres savent quoi faire ;
- la documentation est à jour ;
- aucune décision importante n’est perdue ;
- le projet reste cohérent dans son ensemble.

# Fonctionnement collectif

Chaque décision importante suit le processus suivant :

1.  Proposition.
2.  Discussion collective.
3.  Questions et critiques.
4.  Recherche de consensus.
5.  Validation finale par le chef de projet.

# Rappel important

Le projet IFRI MentorLink est un travail collectif.

Chaque membre possède une responsabilité principale, mais tous doivent comprendre :

- le modèle de données ;
- le fonctionnement du backend ;
- le fonctionnement du frontend ;
- le système de matching ;
- le système de messagerie ;
- les principes généraux de l’architecture.

L’objectif final est que chaque membre soit capable de présenter et défendre le projet lors de la soutenance.
