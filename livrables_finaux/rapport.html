Introduction

Dans le cadre du projet intégrateur de première année de licence à l'IFRI, notre groupe a développé une plateforme web nommée IFRI MentorLink. Cette application facilite la mise en relation entre étudiants mentors et étudiants mentorés, favorisant l'entraide académique et professionnelle au sein de l'IFRI.

Le projet répond directement au cahier des charges fourni par les encadreurs et s'inscrit dans une démarche complète de développement logiciel, réalisé dans un délai court de dix jours, nécessitant une forte coordination entre les membres du groupe.

Contexte & Problématique

À l'IFRI, de nombreux étudiants possèdent des compétences solides dans certaines matières, tandis que d'autres rencontrent des difficultés dans ces mêmes domaines — sans système structuré pour les mettre en relation.

Problèmes identifiés

  • Pas de système pour identifier les étudiants compétents
  • Difficulté à trouver un mentor rapidement
  • Pas de gestion centralisée des disponibilités
  • Communication difficile entre pairs
  • Aucune centralisation des offres et demandes de mentorat

Solutions apportées

  • Création de profils étudiants détaillés
  • Publication d'offres et demandes de mentorat
  • Matching automatique par score de compatibilité
  • Messagerie intégrée entre utilisateurs
  • Système de notifications en temps réel

Objectifs du Projet

Objectif général : Développer une plateforme web de mentorat étudiant permettant la mise en relation intelligente entre mentors et mentorés.

Phase 1

Phase 2
Développement Parallèle

Développement simultané : backend Django (modèles, vues, API) et frontend (templates Bootstrap, pages statiques). Commits réguliers.

Phase 3

Connexion des templates Django, adaptation des routes, correction des chemins statiques, tests collectifs d'intégration.

Phase 4
Tests & Livraison

Tests fonctionnels, résolution des erreurs finales, validation de l'ensemble des fonctionnalités, documentation finale.

Gestion Collaborative avec GitHub

Branches principales

● main — branche de production
● develop — intégration continue
● feature/integration-frontend-backend
● Branches spécifiques par membre

Workflow Git adopté

  1. Création d'une branche spécifique
  2. Développement individuel
  3. Commits réguliers & descriptifs
  4. Push sur GitHub
  5. Fusion progressive vers develop
  6. Tests collectifs & merge vers main

Cette approche a permis de limiter les conflits, d'assurer la traçabilité du code, d'améliorer la collaboration et de protéger la branche principale.

Chapitre 05

Guide d'Installation & Déploiement

Instructions complètes pour installer et lancer le projet IFRI MentorLink en environnement local.

Prérequis

Python Version 3.11 ou supérieure
PostgreSQL + pgAdmin recommandé
Git Pour cloner le dépôt
bash — Vérification des installations
# Vérifier Python python --version # ou: py --version # Vérifier Git git --version # Vérifier PostgreSQL psql --version

Étapes d'Installation

1
Cloner le projet

Cloner le dépôt GitHub et entrer dans le répertoire du projet.

bash
git clone https://github.com/NOM_DU_GROUPE/PIL1_2526_03.git cd PIL1_2526_03
2
Accéder au backend Django

Le backend Django se trouve dans le dossier backend/.

bash
cd backend
3
Créer et activer l'environnement virtuel

Créer un environnement Python isolé pour le projet.

bash — Windows / Linux / Mac
# Créer l'environnement python -m venv .venv # Windows python3 -m venv .venv # Linux / Mac # Activer l'environnement .venv\Scripts\Activate.ps1 # Windows PowerShell .venv\Scripts\activate.bat # Windows CMD source .venv/bin/activate # Linux / Mac # L'activation est confirmée par : (.venv)
4
Installer les dépendances

Installe Django, psycopg2, channels, pillow et toutes les bibliothèques nécessaires.

bash
pip install -r requirements.txt
5
Créer la base de données PostgreSQL

Dans pgAdmin, créer une nouvelle base nommée mentorlink_db.

6
Configurer le fichier .env

Créer un fichier .env dans le dossier backend avec les paramètres de connexion.

.env — Configuration
DEBUG=True SECRET_KEY=django-insecure-mentorlink-secret-key DB_NAME=mentorlink_db DB_USER=postgres DB_PASSWORD=VOTRE_MOT_DE_PASSE_POSTGRES DB_HOST=localhost DB_PORT=5432
7
Importer la base SQL

Dans pgAdmin → sélectionner mentorlink_db → Tools → Query Tool → ouvrir mentorlink.sql → exécuter.

8
Exécuter les migrations Django

Applique les migrations pour synchroniser Django avec la base de données.

bash
python manage.py makemigrations python manage.py migrate python manage.py check # Doit afficher : System check identified no issues
9
Créer un super utilisateur (optionnel)

Permet d'accéder à l'interface d'administration Django via /admin/.

bash
python manage.py createsuperuser
10
Lancer le serveur Django

Le projet sera accessible sur http://127.0.0.1:8000/

bash
python manage.py runserver # Accès à l'application : http://127.0.0.1:8000/ # Administration Django : http://127.0.0.1:8000/admin/

Démarrage Rapide

Résumé en une commande pour relancer le projet après installation.

bash — Quickstart
cd PIL1_2526_03 && cd backend .venv\Scripts\Activate.ps1 # Windows PowerShell python manage.py check python manage.py runserver

Résolution des Erreurs Fréquentes

manage.py introuvable
can't open file 'manage.py': No such file or directory
Se placer dans le dossier backend/ : cd backend
Module Django introuvable
ModuleNotFoundError: No module named 'django'
Activer l'environnement virtuel puis : pip install -r requirements.txt
Erreur d'authentification PostgreSQL
password authentication failed for user "postgres"
Vérifier le mot de passe dans le fichier .env, le nom de la base et l'état de PostgreSQL.

Chapitre 06

Bilan & Conclusion

Difficultés surmontées, solutions mises en œuvre, utilisation de l'IA, état du projet et perspectives.

Difficultés Rencontrées

Intégration Frontend / Backend

La connexion des templates HTML avec Django a nécessité une restructuration des pages, l'adaptation des routes, l'intégration des templates Django et la correction des chemins statiques.

Gestion Git

Le groupe a rencontré des conflits Git, des erreurs de branches et des problèmes de synchronisation entre les différents membres de l'équipe.

Gestion du temps

Le délai de développement très court (10 jours) a nécessité des réunions fréquentes, une forte coordination et une priorisation rigoureuse des tâches.

Différences de niveau technique

Les membres avaient des niveaux variés en Django, Git et PostgreSQL. Cela a nécessité des formations internes, des explications et des démonstrations pratiques.

Solutions Apportées

Solution 1
Modularisation du projet

Le projet a été découpé en modules Django indépendants, permettant à chaque membre de travailler sur son domaine sans bloquer les autres.

Solution 2
Documentation continue

Chaque membre documentait régulièrement son travail, facilitant la transmission d'information et la résolution des conflits d'intégration.

Solution 3
Réunions quotidiennes à 18h30

Les réunions journalières permettaient de suivre l'avancement, d'identifier les blocages et d'ajuster les priorités en temps réel.

Solution 4
Intégration progressive

Les fonctionnalités ont été intégrées progressivement (frontend statique → backend → connexion templates) pour limiter les erreurs cumulées.
